# 06. Database Architect Report — Monitoring Platform Database Schema & Indexing

## 1. Схема базы данных (ER-структура)
В соответствии с `backend/app/models.py`, база данных содержит следующие основные таблицы:
- `organizations` — Клиентские организации (арендаторы SaaS).
- `users` — Пользователи (администраторы, пользователи и наблюдатели организаций).
- `servers` — Мониторяемые серверы. Привязаны к `organizations.id` через внешний ключ (`org_id`).
- `websites` — Мониторяемые веб-сайты. Привязаны к `organizations.id`.
- `metrics` — Временные ряды метрик серверов (CPU, RAM, Disk и т.д.).
- `probes` — Результаты HTTP/HTTPS проверок доступности сайтов.
- `logs` — Системные логи серверов.

---

## 2. Анализ производительности и оптимизация индексов
Таблицы `metrics`, `logs` и `probes` являются высоконагруженными по записи (write-heavy). На масштабе SaaS (до 50 000 агентов) они будут расти со скоростью миллионов записей в день.

### 2.1 Существующие индексы (Проверено):
- `ix_metrics_server_time` на полях `(server_id, received_at)` — обеспечивает быстрый выбор исторических графиков для конкретного сервера.
- `ix_probes_website_id` и `ix_probes_received_at` — ускоряют выборку доступности сайтов.

### 2.2 Рекомендации по оптимизации для SaaS-масштаба:
1. **Секционирование таблиц (Table Partitioning)**:
   - Таблицу `metrics` и `logs` необходимо секционировать по дням или неделям на основе поля `received_at`. Это позволит быстро удалять старые метрики через `DROP PARTITION` вместо тяжелых запросов `DELETE`, блокирующих всю БД.
2. **Композитные индексы с учетом организации (Tenant-first Indexing)**:
   - При выборке данных для панели пользователя мы всегда фильтруем по `org_id`.
   - Необходимо добавить композитный индекс на таблицу `servers`: `CREATE INDEX ix_servers_org_id ON servers(org_id);`
   - Добавить композитный индекс на таблицу `websites`: `CREATE INDEX ix_websites_org_id ON websites(org_id);`
3. **Очистка (Pruning)**:
   - Внедрить Celery-задачу для автоматической очистки метрик старше 30 дней (Retention Policy).

## 3. План действий (Action Items)
- Добавить индексы на внешние ключи `org_id` в таблицах `servers` и `websites`.
- Настроить retention-скрипт для удаления старых метрик.
- Начать проектирование секционирования PostgreSQL при переходе рубежа в 10 000 агентов.
