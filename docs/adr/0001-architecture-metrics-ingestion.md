# ADR 0001: Архитектура сбора и хранения высокочастотных метрик

## Статус
Принято (Approved)

## Контекст
Система должна собирать метрики системного уровня (CPU, RAM, диски, сеть, процессы) с сотен серверов каждые 15 секунд. Прямая запись сырых JSON-пакетов в реляционную таблицу приведет к быстрому разрастанию базы данных (миллионы записей в месяц) и замедлению запросов истории (`SELECT`).

## Решение
1. **Буферизация на стороне агента**: Агент накапливает метрики в локальном буфере при временной недоступности сети (до 25 пакетов), исключая потерю данных.
2. **Разделение слоев (Write/Read)**: Бэкенд сохраняет сырые данные в оперативную память (`AGENT_METRICS` / Redis) для мгновенного отображения статуса "Online". Запись в PostgreSQL `metrics` происходит асинхронно через фоновые задачи (`asyncio.create_task`).
3. **План масштабирования**: 
   - Внедрить партиционирование (разбиение по неделям) для таблицы `metrics`.
   - Добавить Celery task для агрегации старых данных (старше 7 дней) в средние показатели за час и автоматического удаления сырых логов.

## Последствия
* **Плюсы**: Низкая задержка записи, стабильное время отклика API, гарантированная сохранность данных.
* **Минусы**: Временное расхождение данных в памяти и на диске при аварийном завершении бэкенда (до завершения записи задачи).
